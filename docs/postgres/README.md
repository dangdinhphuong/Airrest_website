# Airrest — schema PostgreSQL (Supabase)

Nguồn sự thật: [backend/database/migrations/](../../backend/database/migrations/) (SQL thuần, áp bằng `npm run db:migrate`, ghi vết ở `schema_migrations`).
Thiết kế nghiệp vụ gốc vẫn là [docs/mongodb/THIET_KE_MONGODB_AIRREST.md](../mongodb/THIET_KE_MONGODB_AIRREST.md); bảng dưới là phép chuyển sang quan hệ.

| Collection Mongo | Bảng Postgres | Khác biệt đáng chú ý |
|---|---|---|
| hotels, roles, accounts, room_types | cùng tên | giá trị lồng (địa chỉ, chính sách, vị trí, sân bay, tài khoản nhận tiền) để `jsonb`; sân bay lọc bằng `airports @> '[{"iata":"HAN"}]'` (GIN) |
| bookings | bookings | `payment.*` tách thành cột `payment_method/payment_status/paid_vnd/refunded_vnd`; `stay_from` là bản sao của `stay.from` để index |
| room_reservations (`from`,`to`) | room_reservations (`starts_at`,`ends_at`) | |
| inventory_locks | — | thay bằng `SELECT … FOR UPDATE` trên dòng `room_types` trong transaction đặt phòng |
| payments, refunds | payments, refunds | unique `txn_ref` (trước migration 002 là `momo_order_id`; cột `momo` đổi thành `gateway`), `refunds.key` thay unique index Mongo |
| ledger_entries | ledger_entries | chỉ thêm; `ref_type/ref_id` |
| audit_logs | audit_logs | khóa `id` identity tăng dần dùng làm con trỏ phân trang |
| system_configs | system_configs | `UNIQUE (key, version)` |
| idempotency_keys (TTL) | idempotency_keys | không có TTL tự động: dọn khi gặp lại key hết hạn |
| (mới, migration 003) room_blocks + cột mới của room_types | room_blocks | khóa/bảo trì phòng theo khoảng giờ (`qty`, `released_at`); `room_types` thêm `code` (unique theo khách sạn), `capacity`, `beds`, `area_m2`, `retired_at`. Tồn = `room_reservations` đang hoạt động + `room_blocks` chưa gỡ |
| (mới, migration 004) booking_decisions | booking_decisions | quyết định của khách sạn với đơn chờ: CONFIRMED / REJECTED (bắt buộc lý do) / EXPIRED, kèm `alternatives` (tối đa 3 khách sạn gợi ý). Khách sạn tạo mới mặc định `approval.manual = true`; hạn chờ lấy từ `booking.hold.approvalExpireMin` |
| (mới, migration 005) change_requests | change_requests | yêu cầu hủy/đổi ngày của khách; `UNIQUE (booking_id) WHERE status='PENDING'` (một yêu cầu đang chờ mỗi đơn); `quote` chốt lúc gửi (BR-CXL-03). Lệnh hoàn do hủy/đổi: `refunds.key = 'cancel:<id>'` / `'change:<id>'`, `due_at = 'infinity'` (chưa thực thi, thanh toán đang tạm dừng) |
| (mới, migration 006) support_tickets, support_messages | cùng tên | ticket hỗ trợ (`code` SP-xxxxxxxx) + tin nhắn; `internal = true` là ghi chú nội bộ, không trả cho khách |
| (mới, migration 024) accounts.preferences, support_tickets.account_id | cùng tên | `accounts.preferences jsonb` (chỉ PASSENGER): cấu hình cá nhân `{airport, adults, children, rooms, paymentMethod}`, KHÔNG chứa SĐT/email (BR-002); `support_tickets.account_id` (NULL = khách vãng lai, ON DELETE SET NULL) để liệt kê "yêu cầu hỗ trợ của tôi" |
| (mới, migration 023) support_attachments | cùng tên | ảnh/video khách đính kèm ticket: `storage_key` (R2, bucket riêng tư, server đặt), `content_type`, `size_bytes` (ghi đè bằng số thật sau xác minh), `status` PENDING→READY; PENDING quá 24 giờ bị job dọn |
| (mới, migration 007) shuttle_requests | shuttle_requests | xe đưa đón gắn booking; giá chốt lúc tạo (`price_vnd`, `config_version`); `UNIQUE (booking_id, direction) WHERE status IN ('REQUESTED','ASSIGNED')`; `distance_km` lấy từ `hotels.airports` (không gọi định tuyến) |
| (mới, migration 008) flights, flight_changes | cùng tên | chuyến bay MÔ PHỎNG + lịch sử đổi giờ; `flight_date` là cột sinh theo giờ VN, `UNIQUE (code, flight_date)` |
| (mới, migration 017) payers, payer_stations, payer_hotel_rates, delay_batches, delay_groups, delay_flight_pax, delay_room_offers | cùng tên | luồng đặt phòng cho khách delay chuyến (spec `docs/superpowers/specs/2026-11-14-airport-delay-booking-design.md`). `payers` + `payer_stations` (trạm ↔ sân bay IATA, `UNIQUE (payer_id, airport_iata)`); `payer_hotel_rates` = giá hợp đồng theo loại phòng (`night_rate_vnd`, `hourly_rates` jsonb `[{hours, priceVnd}]`, `commission_pct`, hiệu lực `valid_from/valid_to`); `delay_flight_pax` unique `(flight_id, pnr, lower(full_name))`, `category` khớp `age` (INFANT <2, CHILD 2-11, ADULT >=12) bằng CHECK; `delay_groups.no_split` = cụm không tách; `delay_room_offers` = từng lượt gửi KS (`expires_at` hạn 5', `transfer_count`, `rejected_hotel_ids`, `room_numbers`). Chưa có `payer_statements` (GĐ5) |
| (mở rộng, migration 017) | cột mới trên bảng cũ | `bookings`: `payment_method` thêm `PAYER`, `batch_id`, `group_id`, `simulated`; `accounts`: `type` thêm `PAYER`, `payer_id`, `payer_station_id` (CHECK: PAYER <=> có `payer_id`); `room_types`: `bed_type` (SINGLE/DOUBLE/TWIN/FAMILY), `connecting`, `family` (sức chứa/số giường đã có từ 003); `vehicles.child_seats`; `flights.simulated` (mặc định true: mọi chuyến hiện có là mô phỏng). Đơn/chuyến `simulated` bị loại khỏi kết toán |
| (mới, migration 018) payer_api_keys, payer_ingest_logs | cùng tên | cổng kết nối đơn vị chi trả. `payer_api_keys`: nhiều khóa/đơn vị, CHỈ lưu `key_hash` (sha256 hex, unique) + `key_prefix` để nhận diện, thu hồi bằng `revoked_at`, `last_used_at` ghi mỗi lần dùng. `payer_ingest_logs`: mỗi lần đẩy (`source` API/SIMULATION, `result` OK/REJECTED, `flight_id`, `summary` jsonb chỉ chứa số liệu tóm tắt, không có họ tên/email/SĐT khách, `error_code/error_message`) |
| (mở rộng, migration 019) | cột mới | dịch vụ lô đặt phòng delay: `delay_groups.code` (mã nhóm hiển thị `NH-xxxxxxxx`, unique, hàng cũ null); `delay_room_offers.pax_ids uuid[]` (khách trong từng đơn vị đặt; 1 offer = 1 phòng hoặc 1 cụm phòng thông nhau, `qty` = số phòng); `delay_batches.idempotency_key` + unique `(payer_id, idempotency_key)`; `delay_batches.result` jsonb `{unplaced:[{paxId,pnr,reason}]}`; `delay_flight_pax.contact_email/contact_phone` = liên hệ nhân viên quầy sửa, chỉ áp dụng cho đơn, không ghi đè `email/phone` gốc của hãng. Khách có "đơn hiệu lực" khi `group_id` trỏ nhóm ở trạng thái PENDING/OFFERED/CONFIRMED |
| (mới, migration 020) email_outbox | email_outbox | hộp thư đi cho email giao dịch. `status` PENDING/SENDING/SENT/FAILED/DEAD; `attempts` tăng khi worker nhận thư; `next_attempt_at` = hạn thử lại (SENDING: hạn thuê, quá hạn thì nhặt lại); `dedupe_key` unique nullable chống gửi trùng cùng sự kiện; `payload` chỉ để tra cứu/in lại, nội dung gửi nằm ở `subject/body_text/body_html`. Worker lấy hàng bằng `FOR UPDATE SKIP LOCKED` |
| (mở rộng, migration 022) | cột mới | `delay_batches.pickup_point` text <= 200: điểm đón ở sân bay của lô (chọn từ danh sách cố định theo sân bay, `backend/data/pickupPoints.ts`), dùng làm `location` của yêu cầu xe TO_HOTEL. Xe delay (GĐ3) dùng lại `shuttle_requests` (`billed=false`, `price_vnd` = chi phí xe để quyết toán GĐ5, không vào `bookings.pricing`) và `shuttle_trips` |
| (mở rộng, migration 025) | cột mới | `delay_room_offers`: `extension_status` NONE/PROPOSED/REQUESTED/ACCEPTED/REJECTED (mặc định NONE) — luồng gia hạn khi giờ bay đổi muộn hơn giờ rời KS: hệ thống ghi PROPOSED + `proposed_leave_at`, quầy yêu cầu (REQUESTED, `extension_requested_at`), KS đồng ý/từ chối (`extension_responded_at`). Không tự gia hạn; chi phí gia hạn = `bookings.pricing.roomVnd` đã cập nhật theo khung mới khi ACCEPTED |
| (mở rộng, migration 026) | cột mới | nâng hạng phòng tại quầy (spec 6.8): `payers.allow_upgrade` boolean mặc định false (admin bật qua PATCH /v1/admin/payers/:id); `delay_room_offers.upgrade_from_room_type_id` (hạng chuẩn ban đầu) + `upgrade_delta_vnd` (> 0, tổng phần chênh giá hợp đồng; hai cột cùng null hoặc cùng có) — khi đã nâng thì `room_type_id` là hạng ĐÃ nâng và `bookings.pricing.roomVnd` là giá hợp đồng hạng nâng. Kết toán tách dòng ROOM (= roomVnd - delta) và UPGRADE_DELTA (= delta); hoa hồng tính trên tổng. Chuyển khách sạn thì offer mới không có cột nâng hạng |
| (mới, migration 024_settlements) payer_statements, payer_statement_lines, hotel_payouts, hotel_payout_lines | cùng tên | kết toán THÁNG hai chiều (GĐ5). `period` = 'YYYY-MM' theo giờ VN, đơn thuộc kỳ theo tháng của `stay.to`. `payer_statements` (UNIQUE payer_id+period; DRAFT/SENT/DISPUTED/LOCKED; `dispute_deadline` = sent_at + 5 ngày; tổng theo loại + `version`) và dòng ROOM/SHUTTLE/ADJUSTMENT/UPGRADE_DELTA (`amount_vnd` bigint có dấu, `commission_vnd`). `hotel_payouts` (UNIQUE hotel_id+period; DRAFT/LOCKED/PAID; `net = gross - commission`, CHECK ở dòng) và dòng ROOM/ADJUSTMENT. Hoa hồng làm tròn XUỐNG từng dòng; tổng = SUM các dòng. Đơn/lô/chuyến `simulated` không vào. Điều chỉnh sau khóa ghi vào kỳ nháp kế tiếp |
| (migration 002) | — | đổi cổng thanh toán MoMo → VNPay: `momo_order_id`→`txn_ref`, `momo`→`gateway`, `momoRetries`→`gatewayRetries` |
| Change Stream `bookings` | `services/events.ts` | phát sự kiện sau commit, trong một tiến trình |

Quy ước: khóa chính `uuid` (`gen_random_uuid()`); bảng cần phân trang có `seq` identity làm con trỏ keyset; tiền `bigint` VND; thời gian `timestamptz`.
Sửa schema: thêm file `NNN_ten.sql` mới, không sửa file đã áp; cập nhật bảng này và `backend/database/types.ts`.
